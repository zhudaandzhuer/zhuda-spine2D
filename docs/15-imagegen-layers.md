# 15 生成圖／手繪圖 → 分層零件

影像模型給的是一張平面圖；骨架要的是每個部位獨立、被遮住的地方也畫滿的零件。這一段把前者變成後者，輸出和 `spk art` 完全相同的 `parts/`，之後直接 `spk build`。

```sh
python3 spk.py layers DIR --init        # 產生 layers.json 起始檔、PROMPTS.md、gen/
# 依 PROMPTS.md 生成：gen/keyart.png（主視覺）＋每層一張，同尺寸、同位置、純色背景
python3 spk.py grid gen/keyart.png      # 帶座標的格線圖：讀多邊形座標用（--crop x,y,w,h 放大局部）
python3 spk.py layers DIR               # 去背 → 對位 → 切割 → parts/ + manifest + 檢查圖
python3 spk.py key IMG --out OUT        # 單張去背（想先看一張的去背品質時用）
```

## 原則

1. **先有一張通過 G1 的主視覺，再從它衍生圖層。** 各層獨立發想會讓光影、線條、比例對不起來。
2. **可見的小東西從主視覺切**（眉、鼻、嘴、睫毛、眼白）：像素和主視覺一致，不需要對位。
3. **有隱藏區的大東西另外生成**（後髮、身體、脖子、手臂、沒有五官的臉）：請模型把被擋住的部分補出來。
4. **需要「和底下完全同色」的補片用 `@part` 複製**（眼皮補片從 `face` 複製再羽化上緣）。
5. **圖層要是不透明實體。** 半透明、模糊、發光的東西不要單獨放在色底上生成（去背後會偏色）：從主視覺切，或在 `layers.json` 用 `fade` 做淡出。
6. 工具不會創造像素。缺的隱藏區只能回去補圖。

## `layers.json`

```json
{
  "keyart": "gen/keyart.png",          // 主視覺；有它才有對位、recompose 檢查、spk fidelity
  "canvas": [1024, 1536],              // 省略時取主視覺尺寸
  "background": "auto",                // 來源圖的純色背景：auto | "#00ff00" | null（已有真 alpha）
  "resize": false,                     // true：尺寸不同的來源圖直接縮放到畫布（不建議）
  "key_mode": "global",                // border：只去掉與邊框相連的背景（保護被包住的同色區）
  "defaults": {"align": true, "despeckle": 2},
  "min_overlap": 6,                    // 接縫檢查要求的底層延伸量（px）
  "parts": [ … ]                       // 順序 = 由後到前 = slot 順序
}
```

每個 part：

| 欄位 | 說明 |
|---|---|
| `name` | 唯一；之後 `rig.part(name, …)` 用它 |
| `source` | `"gen/x.png"`（獨立圖檔）、`"keyart"`（從主視覺切）、`"@face"`（從前面已完成的 part 複製，像素相同） |
| `key` | 是否去背。預設跟隨 `background`；可給 `"#rrggbb"` 指定該張的背景色 |
| `align` | 把這張對到主視覺。`true` 只找位移（±24px）；`{"scale": true}` 另試 0.98–1.02；`{"search": 40}` 加大範圍 |
| `place` | 手動放置 `{"dx": 3, "dy": -5, "scale": 1.0}`，取代 `align`（收到「weakly constrained」警告、看圖確認偏了之後用） |
| `polygon` / `holes` | 只保留多邊形內；`holes` 是要挖掉的多邊形（眼眶）。座標是畫布像素 |
| `feather` | 多邊形邊緣柔化（px）；切硬邊零件用 0 |
| `fade` | `{"top": 9}`：從該零件自己的邊界往內線性淡出（眼皮補片上緣、瀏海上緣） |
| `despeckle` | 清掉細於約 2×N px 的孤立碎點 |
| `hidden` | 同 slot 的替換圖（不在 setup 顯示）。它不在主視覺裡，無法對位：請生成為「同一裁切的編輯」 |

## 讀報告

`spk layers` 印出 JSON，並在 `evidence/art/` 產生檢查圖。**每一張都要打開。**

| 項目 | 看什麼 |
|---|---|
| `keying[]` | 每張來源的背景色、方法、`translucent_share`。`colour-difference`（飽和色背景）對不透明圖＋抗鋸齒邊可靠；`distance`（白／灰／黑背景）遇到柔邊會留色，請改用飽和色重生。`translucent_share` 高會有警告：半透明區的顏色是估計值，會偏色 |
| 棋盤格錯誤 | 模型把「透明」畫成棋盤格 → 直接報錯，只能重生 |
| `alignment[]` | `dx, dy, scale`、`visible`（該零件在主視覺中可見的比例）、`constraint` |
| `constraint: "weak"` 與 `warnings` | 主視覺定不住這個零件：幾乎全被擋住、周圍都是同色、或比例無從判斷。工具保留最小位移並**明說不確定**——看 `recompose.png`，偏了就填 `place` |
| `recompose` / `recompose.png` | 主視覺｜零件疊回去｜差異×4。差異應該只剩邊緣細線；整塊色差＝位置錯、去背錯或層序錯 |
| `layers_preview.png` | 多邊形畫在主視覺上，確認切對地方 |
| `parts_sheet.png`、`keyart_bg.png` | 每個零件單獨看、主視覺在深／淺／綠三底 |
| `seam_candidates[]` | 畫面上相鄰的兩個零件，下層有沒有延伸到上層底下。`underpaint` 低＝對接縫，任何一邊一動就露底。`backed_by` 列出那條縫底下還有誰：`iris` 後面是 `eye_white` 沒問題；`neck` 後面是 `hair_back` 就是穿幫 |
| `coverage.png` | 每個像素被幾層蓋住。只有 1 層的區域＝底下沒東西 |

`seam_candidates` 只在兩個零件**各自會動**時才是問題（同一根骨上的兩片不用理）。`spk art`（程式畫的美術）也會跑同一個接縫檢查。

## 對位能做到什麼、做不到什麼

演算法：由前往後逐件處理；已放好的前景零件會遮掉後面零件的「投票」。分數＝顏色吻合（完全相同才高分）－ 零件邊緣外主視覺仍延續同色（代表零件該更長）－ 零件超出主視覺輪廓（不可能的位置）。

- 有可見結構的零件（臉、手臂、前垂髮、頭頂髮片）：位移可以對回來。
- 沿著一束均勻髮絲的方向本來就沒有資訊，會取最小位移。
- 大半被擋住或整片同色的零件（後髮、被衣服蓋住的脖子）：會標 `weak`，要你看圖決定。
- 1% 等級的比例漂移只有在零件有足夠紋理時才分得出來；分不出來會標 `weak`。**最好的做法是生成時就鎖住尺寸與位置**，不要依賴對位。

## 驗證範圍（誠實說明）

這條路徑是用**替身資料**驗證的，不是真的影像模型輸出：把 `examples/shuang` 的 36 個零件各自貼回純綠底、對 11 個大件加上 ±7px 位移（其中 2 件再加 1% 縮放）、3 個小件改從壓平的主視覺用多邊形切，然後跑 `layers → build → fidelity → check`（`tests/layers_roundtrip.py`）。

- 結果：9 個只有位移的大件全部對回 ≤2px。兩個加了 1% 縮放的：後髮對回正確比例與位置，但因為只有 6% 可見被標 `weak`；身體的 1% 比例分不出來（角落誤差約 6px），被標 `weak`。臉的位置其實對了，也被標 `weak`（誤報一件）。**沒有任何一件是「錯了卻沒警告」。**
- 依警告對三件填 `place` 後：零件疊回主視覺的差異 0.22% 像素（集中在抗鋸齒邊），`spk fidelity` 通過（0.12%），`spk check` 通過。
- 去背，看圖後的結論：抗鋸齒邊、單一顏色的寬羽化（單元測試：24px 柔邊圓盤，alpha 誤差 <0.06）還原正確，深色描邊不會被吃掉。**但多種顏色疊在半透明區時會偏色**：替身資料裡，單獨放在綠底上的模糊嘴唇變成橄欖色，瀏海淡出帶裡的高光帶綠。這是單色去背的資訊極限（一個像素、三個方程式、四個未知數），不是調參能解的。工具現在會量出「半透明占比」並警告（`translucent_share` > 3%）。
- 所以規則是：**生成的圖層必須是不透明實體**。腮紅、嘴唇、光暈這類柔的東西從主視覺用多邊形切；需要淡出就在 `layers.json` 用 `fade` 做。替身測試已改成嘴巴從主視覺切。
- 這證明的是：去背、對位、切割、manifest 與編譯器相容，而且不確定時會說。
- 這**沒有**證明：影像模型會給你風格一致、位置穩定、隱藏區合理的圖層。替身資料彼此完全一致；真實生成不會。那一段的品質仍然要靠 G1／G2 的看圖把關。
